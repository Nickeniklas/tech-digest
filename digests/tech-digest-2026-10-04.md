## The case for hard spending caps on everything

**What happened**
Simon Willison, a widely read developer and AI commentator, argues that we are going to need default hard budget caps on pretty much every paid service — limits that stop spending outright rather than just sending a warning.

**What this means**
AI assistants and agents increasingly run tasks on pay-as-you-go accounts, so a mistake can quietly turn into a large bill. If you manage a team budget or sign up for AI tools at work, check whether each service lets you set a hard limit — and set one before you need it.

Source: [Simon Willison ↗](https://simonwillison.net/2026/Oct/3/default-hard-budget-caps/)

## Under the Hood

### When an AI agent says "done" but the work isn't

**What happened**
Microsoft published ThinkingBox on the Hugging Face blog, an approach for checking whether an AI agent actually achieved its goal. The core point: a tool call is not an outcome, and one success is not reliability — so it checks the real end state (for example, what is in the database) and measures consistency across repeated runs and its cost.

**Why it matters**
Anyone building agents learns that self-reported success is unreliable. Verifying outcomes against the real system, and pricing in how often a model succeeds, gives a more honest picture of which model to depend on.

Source: [Hugging Face Blog ↗](https://huggingface.co/blog/microsoft/thinkingbox)

### How GitHub opens a million-line pull request

**What happened**
GitHub explained how it rebuilt the code-change viewer in its Copilot app so it can open a pull request with a million changed lines and hundreds of inline review comments.

**Why it matters**
AI agents can produce far larger code changes than people do, so review tools have to keep up. Rendering huge diffs smoothly is a prerequisite for humans actually reviewing what agents write.

Source: [GitHub Blog ↗](https://github.blog/engineering/user-experience/rendering-huge-pull-requests-in-the-github-copilot-app/)
